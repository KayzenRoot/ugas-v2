# M30 — Session 09: DCC Quality Court, Repair & Observability

Status: PLANNED / IMPLEMENTATION-READY CANDIDATE

## Mission
Make autonomous DCC production convergent and observable. Every visible/technical defect must become structured evidence, a causal hypothesis and, where authorized, the smallest bounded repair.

## Quality stack
DCC validation -> GHP -> topology/UV/bake/material courts -> deformation court -> target-camera diagnostics -> runtime validation -> M19 Quality Court -> M20 repair loop.

## Proprietary technologies
### DQD — DCC Quality Dossier
A compact machine-readable dossier for each asset/transaction containing current acceptance state, hard-gate results, scored dimensions, unresolved defects, proof fingerprints, diagnostic artifacts and repair debt.

### CDR-DCC — Causal Defect Router for DCC
Maps symptoms to likely DCC causes and requests the cheapest discriminating diagnostic before repair. Example: a dark seam may originate in UV, tangent basis, bake cage, normal orientation, material channel or runtime import.

### RIM — Repair Invalidation Matrix
Defines exactly which proofs are invalidated by each DCC repair class and region. It operationalizes the project rule: test what changed, reuse what did not.

### AQC-DCC — Autonomous Quality Convergence
Chooses bounded repair candidates using expected quality gain, confidence, cost, remaining budget and regression risk. Stops on acceptance, non-improvement, oscillation, exhausted budget or required human/product escalation.

## Diagnostic render suite
Beauty, clay, wireframe, normals, UV checker, material channels, silhouette, depth, contact, target-camera near/mid/far, deformation stress, runtime-equivalent and failure-specific views.

## M26 dashboard
Shows stage, transaction/op, asset, DQD state, defects, failed gates, repair attempts, proof reuse, CPU/RAM/GPU/VRAM, cache, route/tool/model, ETA, cost, artifact lineage and last valid checkpoint.

## No infinite loops
Repeated equivalent repair without measurable improvement is forbidden. Oscillation and non-improving residuals trigger route change or escalation.

## Acceptance
An intentionally defective asset can be diagnosed to a bounded cause, repaired through DCC-IR, selectively revalidated and shown in the dashboard with complete causal/evidence history.
